## Description

Implements `ChatService` (`src/app/copilot/services/chat.service.ts`), the orchestration layer for the Mifos Copilot chat flow: sanitize -> stream via `McpClientService` -> parse -> persist.

- `sendMessage()`: sanitizes input via `InputSanitizer`, appends the user message (with the focused client id from `AiContextService`), and streams the assistant reply. Blocked input (empty/over-length/prompt-injection) short-circuits with a system message and never calls the MCP client.
- Handles `token` events by incrementally re-parsing the buffered text through `ResponseParser`, `action_card` events by merging directly-streamed cards with any parsed from fenced blocks, and `tool_call` events by routing through `McpClientService.handleToolCall()` (wrapped defensively so a not-yet-wired tool-call handler can't break the token stream).
- `error` events and transport failures finalize the message with a readable error string instead of throwing; a synchronous throw from `McpClientService.sendMessage()` (it is not implemented yet) is also caught and degrades gracefully.
- `stopStreaming()` unsubscribes the active stream and freezes the partial message; `clearChat()` stops any active stream and resets the message list and session id.
- `loadHistory()` reads `GET {mcpBaseUrl}/api/chat/history/{userId}` when a user id is known, falling back to a `localStorage` cache (`copilot_chat_history`) on request failure or when no user id is available. Completed turns are upserted into `conversations$` and cached locally for the Recent Chats tab.

Covered by `chat.service.spec.ts` (18 tests): streaming/finalization, action-card merging, tool-call routing (including a throwing handler), error paths (in-band error event, transport error, synchronous throw), `stopStreaming`, `clearChat`, and all three `loadHistory` branches.
